# watch you
# AI 健康与情绪助手 · 完整产品需求文档

版本：v2.0｜需求基线：2026-10-21｜状态：完整需求与交互原型，原生实机接入未完成

项目：Yurken/watchYou｜展示名称：watch you｜目标平台：iPhone + Apple Watch

本版以 AI 自动情绪推断、全模块 AI 分析、通用数据来源与自定义模型服务为核心。文档的产品规则、公式权重和门槛是待验证的工程设计，不是医学结论；原型全部健康数据为合成示例。真实模型调用不等于真实 HealthKit 接入，结构校验通过不等于推断准确。

## 01 产品定位与需求基线

### 1.1 产品名称与目标

正式产品名称为 **watch you**，全部小写、单词间一个空格。代码仓库标识为 **Yurken/watchYou**；源代码模块可采用 WatchYou / WatchYouCore，Bundle ID 在完成签名验证后固定。文档、页面、导出文件和新工程不再沿用旧暂定品牌。

watch you 是面向个人的 iPhone + Apple Watch AI 健康助手。它把睡眠、心率与 HRV、情绪倾向、恢复、运动与习惯汇总为可解释的洞察，而非要求用户持续填表。手机承担数据治理、模型调用、历史分析与设置；手表呈现状态摘要、低打扰建议和轻量操作。

### 1.2 本次确认的产品决策

| 决策 | 必须体现的产品行为 |
| --- | --- |
| 情绪由 AI 自动推断 | 默认展示推断、时间线、依据与不确定性；不以打卡作为运行前提 |
| 不突出设备数量 | 首页、导航与状态卡不出现固定设备对比；仅在详情和设置展示通用数据来源 |
| AI 全面融入 | 今日、睡眠、心率、恢复、运动、习惯、情绪、报告和问答使用统一 AI 能力 |
| 服务可自定义 | 在设置中配置 URL、Model、认证、密钥与调用参数；支持多组服务 |
| 功能集中、便于重签 | 一个仓库和工作区组织手机与手表；不拆为多个独立产品 |
| 不伪装能力 | 原始观测、用户反馈和 AI 推断分层；没有证据就保留未知 |

### 1.3 成功标准

用户完成 HealthKit 接入与一次 AI 范围授权后，无需主动打卡，也能在有新数据且系统允许运行时获得自动分析；每条洞察能追溯到时间窗、证据与模型；切换服务后不会把旧密钥或旧授权带到新接收端；无网络仍能查看原始记录、已缓存结果及其日期。

自动推断是一种产品行为，不等同于已证明能够准确识别真实心理状态。首版必须同时交付数据质量门控、未知状态、可选纠正和可复核的评估流程。高调用频率、漂亮图表或模型自报的高信心不作为成功指标。

## 02 范围、优先级与非目标

### 2.1 首版范围

| 优先级 | 交付内容 | 验证门槛 |
| --- | --- | --- |
| P0-A | 签名与 HealthKit 探针、Watch 安装通信、AI 配置与无健康数据连接测试 | 保留真实日志；阻断项有结论 |
| P0-B | 数据汇总、自动情绪推断、各模块 AI 解读、问答、来源管理 | 有证据引用、失败降级和授权撤销 |
| P0-C | 缓存、离线习惯记录、备份恢复、手表摘要 | 幂等、重签保留与恢复可验证 |
| P1 | 可选提醒、周月报、个性化反馈校准、复杂功能 | 能耗、错误提醒和隐私验证 |
| P2 | 多模态主动输入、端侧模型、更多有数据的指标 | 单独确认权限、能力与评估范围 |

AI 已从后期附加功能调整为首版横贯能力；“关闭 AI 后原始数据仍可用”是故障与隐私降级，不代表 AI 不重要。睡眠、恢复等基础数值先由本地确定性算法产生，模型负责推断、解释与建议，不把全部数值计算交给大模型。

### 2.2 明确不做

不作疾病诊断、抑郁/焦虑筛查或紧急医疗监控；不从稀疏心率单独断言“你正在愤怒”；不虚构全天情绪曲线；不自动开启麦克风、读取其他 App 私密内容或上传完整健康库；不借虚假运动会话绕过后台限制。

不保证免费签名下所有 capability、扩展和后台行为均可用。iOS 18+ / watchOS 11+ 是初始工程目标，不替代实际设备系统与 SDK 兼容性验证。高级指标按型号、地区、系统与实际可读记录逐项开启。

## 03 信息架构与用户旅程

### 3.1 手机与手表结构

手机底部五个入口为“今日、睡眠、情绪、AI 助手、更多”。更多包含心率与 HRV、恢复与压力、运动与活动、生活习惯、趋势与报告、设置。数据来源作为设置中的二级页面，并可从各指标的来源标签进入，不作为设备数量导向的首页模块。

设置分为 AI 服务、数据范围与隐私、个人目标、提醒、数据来源、备份恢复、签名维护、关于。AI 服务支持配置列表、编辑、连接测试、模型列表、任务开关和调用记录。

手表保留概览、睡眠、AI 情绪、饮水、呼吸五个短流程。AI 情绪页展示推断、证据强度和样本时间，不以选择心情作为主界面；复杂分析与配置留在手机。

### 3.2 核心旅程

| 场景 | 流程 | 完成条件 |
| --- | --- | --- |
| 首次使用 | 简介 → 按需健康授权 → 读取记录 → AI 配置 → 测试 → 预览范围 → 授权 | 不强制打卡；无数据可进入 |
| 自动情绪洞察 | 新摘要 → 质量门控 → 推断 → 校验 → 情绪卡/手表摘要 | 有时间与依据，必要时弃答 |
| 查看睡眠 | 睡眠事实 → 分期 → AI 解释 → 数据来源 | 不把解释冒充新的测量 |
| 提问 | 输入问题 → 限定摘要 → 模型回答 → 证据详情 | 不自动上传全部聊天历史 |
| 纠正判断 | 结果详情 → 可选纠正/补充 → 独立保存 | 不回填原推断为真值 |
| 切换服务 | 修改 URL/Model → 清理旧授权 → 重新确认 | 不向新地址静默发送数据 |
| 每周维护 | 备份 → 原标识覆盖安装 → 检查权限/密钥/队列 | 原始数据与自定义记录可核对 |

## 04 健康接入、权限与同步

### 4.1 授权规则

FR-AUTH-01：首次按使用场景解释数据用途，再调用系统权限界面；初始只请求睡眠、心率、静息心率、HRV、活动与已完成训练的读取。饮水、正念、心境写入在用户开启对应功能时单独申请。[S2]

FR-AUTH-02：授权弹窗成功返回只表示请求流程完成，不能等同于所有读取权限已授予。HealthKit 出于隐私保护不向应用直接暴露每项读取权限是否被拒绝；空结果可能有多种原因。[S2]

FR-AUTH-03：界面使用「可读记录数」「最近成功读取时间」「暂无可读数据」「系统能力不可用」「查询发生错误」等状态；不得把无记录标为权限拒绝。写入状态和读取可见性分开建模。

### 4.2 首次导入与增量更新

建议首次请求最近 90 天，但实际导入仅限系统允许读取的历史范围；提供有限历史授权时按可见记录建基线，不将更早的空白推断为没有发生。能力可用时查询最早授权样本日期，扩展历史由用户主动触发。[S24]分批查询，不在主线程处理大量样本。对支持的类型使用 anchored query 获取新增和删除对象，并持久化查询锚点；删除必须传播到缓存和派生结果。[S10]

使用 observer query 作为变化触发信号，实际数据仍通过查询获取；处理后台投递时遵守完成回调要求。前台进入、用户手动刷新和数据变化均可触发增量更新，但不承诺固定刷新周期。[S11]

FR-SYNC-01：样本入库、派生缓存失效与 anchor 推进在一致性边界内完成；中途失败不得丢更新。FR-SYNC-02：查询失败保留已读取数据但标记缓存时间。FR-SYNC-03：用户撤销访问后不再尝试通过其他路径绕过授权。

### 4.3 验收要求

部分授权仍能使用其余模块；零条记录不会得到零压力或满分睡眠；删除原样本后重新计算；导入中断可以恢复；每个页面明确最近数据时间和最近刷新时间，两者不得混用。

## 05 今日洞察与全局 AI 入口

### 5.1 首页组成

FR-HOME-01：首屏是 AI 今日洞察，一句摘要、主要依据和一个可执行的低风险建议；随后展示睡眠、最近心率、AI 情绪、夜间 HRV、恢复参考。每个事实指标仍保留单位、样本时间和详情入口。

FR-HOME-02：情绪卡显示“可能偏紧绷”等审慎倾向、评估窗口、证据强度与原因入口。没有模型配置、数据不足或过期时显示具体原因，不出现强制心情滑杆或“先打卡才能分析”。

FR-HOME-03：“问问 AI”直达对话；“更新洞察”在摘要未变时优先复用结果，手动强制重算需要遵守预算。没有新样本时不更新时间戳冒充新测量。

FR-HOME-04：所有模型输出区分演示结果、真实模型返回、历史缓存、待分析与分析失败。模拟健康数据即使送入真实模型，也持续显示“基于合成数据”，不可改标为真实健康接入。

### 5.2 交互与提醒

默认先展示简短结论，展开后查看证据、替代解释、模型和版本。AI 失败不影响事实卡；首页不显示密钥、完整提示词或设备数量。来源冲突只在影响当前结论时提供解释入口。

AI 对话不是系统紧急提醒替代品。建议默认留在应用内；开启通知后仍受静默时段、频率上限和用户关闭设置约束。疾病、用药、心理危机等高风险问题不由参考分作安全判断。

## 06 睡眠中心

### 6.1 展示与记录范围

FR-SLEEP-01：读取系统已有睡眠记录，支持清醒、REM、核心、深睡、未细分睡眠与在床状态。核心睡眠不等于深睡；各阶段名称以系统类型为准。[S4]

FR-SLEEP-02：展示主睡眠段、午睡/小睡、累计睡眠时长、分期图、已知清醒时长、目标差距、作息规律和历史趋势。没有分期但有睡眠总段时，只展示「未细分睡眠」，不推算深睡或 REM。

### 6.2 计算口径

总睡眠时长是已选择来源的「睡着」区间并集，不包含清醒和在床区间。在床与分期可能重叠，不得直接相加。相邻分期可用于还原时间轴，但空白区间保持未知。

主睡眠初始按用户作息窗口内最长的合并睡眠段识别；合并间隔、主睡眠窗口与午睡判定均属可配置设计参数，不是医疗定义。用户可以人工更正主睡眠归属，但更正默认作用于本 App，不改写第三方原始样本。

每日归属采用睡眠结束时的本地日期，并记录时区。跨午夜、夏令时与旅行切换时，以绝对时间求时长，以记录时区解释日期；不得用字符串时间直接相减。

### 6.3 参考分与验收

参考分仅以时长达成度、相对个人规律性、记录内连续性计算，不将「深睡比例越高越好」设为目标。连续性不是临床睡眠效率；在床数据不完整时不得冒称效率。

验收：不同来源记录同一晚不翻倍；阶段累计等于去重后已知睡着时间；短暂清醒只计一次；没有记录的区间不进入分母伪造连续性。睡眠评分细则见第 14 节。

### 6.4 AI 睡眠解读

FR-SLEEP-AI-01：AI 只分析本地已计算时长、分期和规律性及有授权的夜间指标；输出影响因素的可能解释和低风险习惯建议。没有分期时不推算深睡/REM；不将阶段比例称作睡眠质量的唯一答案。每条解释可展开证据，建议调整目标时先生成待确认草案。

## 07 心率、静息心率与 HRV

### 7.1 指标定义

FR-HEART-01：心率详情保留时间戳、来源、单位和可获取的运动情境；默认显示最近记录，而非实时心率。实时采集只能作为后续经系统能力验证的主动会话功能。

FR-HEART-02：静息心率优先展示 HealthKit 已有的 restingHeartRate 类型，不把全天最低心率、睡眠最低心率或日均心率冒充静息心率。

FR-HEART-03：HRV 初版使用 HealthKit 的 heartRateVariabilitySDNN，单位 ms。其定义是心搏间期的标准差；不能把它改名为 RMSSD，也不能直接将不同 HRV 定义混入同一基线。[S5]

### 7.2 展示与个人基线

以相近采样情境建立基线：优先夜间或静息时段；主动呼吸练习、运动时段与普通日间采样分别标注。单日使用中位数与样本数，不把不同测量长度的记录无条件合为同一种参考量。

FR-HEART-04：显示近 7 / 28 / 90 天变化、来源筛选与原始记录列表。HRV 不做跨人排行榜；不同设备或算法版本的明显切换应标注基线变化，必要时重建基线。

### 7.3 来源差异与 AI 解读

同一时间附近不同来源存在差异时，保留各自记录，并使用用户为本 App 设置的首选来源显示；比较必须展示实际时间差。暂定相近窗口为 60 秒，这是分析参数，不代表不同来源真正同步测量。

FR-HEART-05：差异提示不自动判定设备损坏或哪块表正确。传感器缺测、佩戴差异与采样时间差不能靠简单平均消除。任何疑似异常提示均不得替代 Apple 自带安全功能或医疗设备。

FR-HEART-AI-01：AI 在相近情境下解释个体变化；日间单次 HRV、夜间中位数和运动后样本分别说明。不能把不同情境的差异直接解释为情绪变坏、设备损坏或疾病。

## 08 AI 自动情绪推断

### 8.1 默认交互与输入层次

FR-EMO-01：无需用户先填写心情。新数据到达后由系统构建近期证据包，自动判断是否具备分析条件；有条件时调用所选模型，缺条件时生成可解释的“暂无法判断”。手动反馈只作为可选校正渠道。

第一层输入是授权后的生理与行为摘要：相近静息情境中的心率/HRV、相对个人基线的变化、睡眠、活动及其时间。第二层是用户自愿提供的文字背景、对 AI 结果的纠正或主动对话；单独授权，不默认上传。第三层为未来可选的主动语音/多模态输入，不在首版自动开启。

Apple 的 State of Mind API 用于表达和记录自愿记录的心境，并不提供一个现成的自动情绪识别器。本产品的情绪推断是独立、待验证的模型能力，不把该 API 的存在当作识别准确性证据。[S3][S6]

### 8.2 推断管线

FR-EMO-02：读取 → 来源治理 → 情境切片 → 特征与个人基线 → 质量门控 → EvidencePacket → AI 推断 → 结构/引用/领域规则校验 → 情绪卡与时间线。模型不得通过文本自行补齐原始样本。

至少区分唤醒程度（低/中/高/未知）、情绪正负向（消极/中性/积极/未知）、倾向标签、替代解释与证据强度。只有生理摘要时允许估计有限的唤醒或紧绷倾向，不强制选择正负情绪；原型限制正负向为 unknown，避免将 HRV 直接映射为悲伤、快乐或焦虑。

FR-EMO-03：允许输出多个候选或未知，不要求每个时刻必须有一种情绪。输出用“可能”“倾向”，不使用“检测到焦虑症”等诊断标签。模型自报概率不得直接展示为准确率。

### 8.3 质量门控与时效

正式算法的样本数、时间窗和基线门槛必须经实测确定并版本化。初始工程参数可使用 60 分钟近期窗口、至少 14 个相近情境有效日；它们只是待验证配置，不是医学标准。跨来源、运动后、近期呼吸训练、基线变更、采样过旧或情境不明时，降低解释力度或停止推断。

FR-EMO-04：模型只能解释输入覆盖的时间窗。必须同时保存 observedAt / window、generatedAt、validUntil；今天生成的解释不得把前天的数据表述为“此刻”。生成时间变新不能延长原观测有效期。

FR-EMO-05：证据强度来自数据覆盖、时间接近性、情境一致性和基线完整度等可检查条件，与概率置信度分开。尚无外部验证时 confidence 为空；不得展示“95% 准确”。

### 8.4 反馈、历史与健康库写入

FR-EMO-06：提供“与感受不符”“补充背景”“纠正倾向”等低负担操作，不弹出强制日问卷。用户反馈作为独立记录，保留对应推断 ID；未反馈不是同意，AI 自己的历史输出不能充当训练真值。

FR-EMO-07：自动推断默认只进入应用内派生记录，不自动写为 HKStateOfMind 的本人自述。只有用户明确确认某条感受，并另行授权系统写入，才可建立独立的“用户确认”心境样本。[S6]

FR-EMO-08：历史时间线只展示真实运行得到的有效窗口，缺测留空、运动干扰显示跳过；不以插值或一次回答生成全天心理状态。用户删除证据或撤销文字使用范围后，相关缓存失效并记录原因。

### 8.5 效果评估

先评价格式合规、证据支持、过期样本拒答、混杂因素处理和不必要诊断率；再在用户自愿参与的反馈样本上评价预测与反馈的一致性。不能用模型评分模型证明情绪准确。后续小样本个人适配采用按时间留出的验证集，报告弃答率、覆盖率与误报，不以降低弃答换取虚高覆盖。

## 09 恢复趋势与生理负荷估计

### 9.1 恢复参考定位

FR-REC-01：恢复参考是基于个人历史的实验性综合指数，用于解释输入变化，不是人体电量、疾病风险概率或运动建议等级。首页可关闭该模块。

FR-REC-02：输入限定为满足质量条件的夜间 HRV、系统静息心率与睡眠参考。基线使用当前日之前的滚动历史，默认最近 28 天，至少 14 个有效日；不得把当天数据泄漏进自己的参照基线。

FR-REC-03：必须展示基线范围、有效天数、缺失输入、样本时间和版本。输入不全则不输出总分，不通过默认值或动态重权来制造可比性。权重与公式见第 14 节。

### 9.2 生理负荷估计

该功能列入 P1 实验模块。心率和 HRV 受多种情境影响，产品不将模型输出命名为确证的心理压力。首次可只展示个人偏离程度与适用条件，不必给 0–100 分。

暂定可计算条件：存在最近 60 分钟内、可归为相近静息情境的 HRV 和心率记录；有足量个人基线；近期运动会话未覆盖该评估窗口；没有明显质量冲突。上述 60 分钟与样本门槛均为待验证配置，而非生理学定论。

FR-LOAD-01：条件不满足则显示原因，例如「最近 HRV 已过期」「缺少情境信息」「正在运动，暂不比较」。无法可靠识别采样情境时，应停止评估而非推断静息。

### 9.3 质量说明

「高/中/低数据完整度」只能描述观测条件，不等于经过校准的置信概率。未经专门验证，不显示「准确率 95%」「情绪可信度 90%」等数值。原型中的当日静息情境 HRV、夜间 HRV 与恢复参考各自标明时间；旧样本不得因生成新解释而冒充当前测量。

### 9.4 AI 恢复解释

FR-REC-AI-01：向模型提供分数及其输入、权重/版本和缺失项，要求解释分项变化而非重算另一套“身体电量”。需要运动安排时结合用户自愿体感，只作低风险参考，不以参考分代替专业评估。

## 10 运动、生活习惯与轻量提醒

### 10.1 运动与活动

FR-ACT-01：读取已完成训练、步数、活动能量和锻炼时间。采用经过多来源测试的聚合策略；禁止将不同来源所有原始累计样本直接相加。系统统计查询的具体行为必须以样例对照验证，而不是假定与健康 App 图表完全一致。

FR-ACT-02：支持训练详情及用户补充主观用力程度 RPE。初版训练负荷可记录为训练分钟数 × RPE，单位标为任意单位；没有 RPE 不补数。RPE 刻度和解释在 UI 明示，负荷只用于个人记录。

### 10.2 习惯与呼吸

FR-HABIT-01：饮水提供自定义目标与 150 / 250 / 500 ml 快捷记录，支持撤销；目标是用户设置，示例目标不是通用医学建议。写入系统数据前单独授权。

FR-HABIT-02：呼吸练习提供自然呼吸节奏、触感开关、计时、停止和完成记录。不要求屏息，明确不适即停止；不承诺练习会提升某个健康数值，不伪造练习后 HRV。

FR-HABIT-03：正式手表版优先使用前台计时；需要后台延长运行时，必须验证适用会话类型与时长，不能当作通用后台常驻方案。[S8]

### 10.3 提醒治理

提醒默认关闭，按睡眠准备、习惯、饮水和维护分别授权与配置。提供静默时段、每日上限、延后和一键关闭；建议初始总上限为每天 3 次非系统提醒，作为可调产品默认值。

本产品不承诺绕过专注模式、失效签名、系统节电或后台调度。实验性恢复分下降不自动告警。原型提醒开关仅演示设置，不创建真实系统通知。

### 10.4 AI 建议与确认

FR-ACT-AI-01：运动、饮水和呼吸建议围绕已记录行为和用户目标形成，不把记录缺失等同于没有饮水/运动。模型只能提出目标或提醒草案，不能自动修改用户设置；未确认不创建通知或写入健康库。

### 11.1 各模块输入与输出

| 模块 | 授权输入 | AI 输出 | 不允许的行为 |
| --- | --- | --- | --- |
| 今日 | 当日摘要、趋势、数据缺口 | 今日状态解释与重点 | 改写观测数值 |
| 情绪 | 近期信号、基线、可选情境 | 倾向、未知项、替代解释 | 生理信号直接诊断 |
| 睡眠 | 已知分期、时长、规律、夜间指标 | 睡眠解读与习惯建议 | 编造 REM / 深睡 |
| 心率/HRV | 类型、情境、样本数、个人基线 | 解释波动与比较边界 | 混用 SDNN/RMSSD |
| 恢复 | 本地参考分、分项、基线 | 解释构成、提示缺口 | 以分数批准运动 |
| 运动 | 已完成训练、负荷、恢复摘要 | 低风险安排建议 | 输出治疗或训练处方 |

### 11.2 统一 AI 基础设施

FR-AI-01：所有功能经 AIOrchestrator 调用共享 ProviderAdapter、EvidenceBuilder、ResultValidator 与 AuditStore，不在每个页面重复硬编码 API。原始数值计算保留在 HealthCore，本地生成事实 ID、单位与来源。

FR-AI-02：任务模板按模块管理，并记录 promptVersion、schemaVersion、model、providerProfileID、sourcePolicyVersion 与算法版本。模板固定安全边界，用户文字作为不可信数据区隔，不提升为系统指令。

FR-AI-03：优先请求结构化输出；供应商支持 JSON Schema 时使用对应接口，兼容服务不支持时可采用 JSON 文本并强校验。结构正确不代表语义或医学结论正确，必须同时检查证据引用与领域规则。[S17][S18][S19]

### 11.3 缓存、错误与降级

缓存键覆盖输入摘要哈希、任务、时间窗、模型/服务、提示词版本、来源策略和授权版本。相同输入不重复自动调用；手动重算仍受预算控制。输入更新后取消过期任务，旧响应不得覆盖新结果。

FR-AI-04：认证失败、超时、限流、无效 JSON、拒答、输出截断或不存在的证据 ID，均显示明确失败与重试入口。不能切换到演示文案冒充模型成功；本地模板降级必须显式标注为规则摘要。

FR-AI-05：未配置服务、用户关闭 AI 或无网络时，原始指标与本地记录仍可用；历史模型结果可展示但保留日期。没有结果时不自动生成新的情绪状态。

### 11.4 问答、报告与动作

问题默认只附当前任务必要摘要。跨期检索与历史对话加入上下文需要可见的范围设置；引用具体事实 ID，相关性来自本地统计而非语言模型计算。报告记录有效日与缺失日，样本不足时写明原因。

FR-AI-ACT-01：模型可提出饮水提醒、睡前准备或习惯目标草案，但修改设置、写入 HealthKit、创建提醒等动作必须由用户确认。首版不暴露任意命令、网页请求或可执行代码工具。

## 12 Apple Watch 体验与通信

### 12.1 手表侧的 AI 呈现

FR-WATCH-01：概览显示一条简短 AI 摘要、最多两项事实指标和数据时间。FR-WATCH-02：睡眠呈现总时长及简要解释。FR-WATCH-03：情绪默认呈现自动估计标签、证据强度、未知项和“查看依据”入口，不展示必填心情选择器。

FR-WATCH-04：饮水与呼吸保留一至两步操作和离线记录。用户愿意纠正情绪时可提供简短反馈，但这不是获取分析的前置条件。模型参数、密钥、长报告和授权详情在手机配置。

手机负责重计算与外部模型调用，手表接收经过裁剪的摘要；不将服务密钥同步到 Watch。手表断开后只显示最后有效结果及日期，必要时标为“历史摘要”，不把连接状态混同为数据来源。

### 12.2 可靠同步

WatchConnectivity 传输当前状态摘要与离线事件。application context 适合可覆盖的最新状态；饮水、反馈等增量事件使用唯一 ID、持久化 outbox、幂等入库与业务确认，不依赖单次即时消息成功。[S9][S12]

事件状态为 localSaved → queued → sent → acknowledged；失败保留队列并按规则重试，删除用 tombstone/版本传播。会话激活、失活与安装实例身份在后台处理，不要求用户理解设备切换机制。

### 12.3 后台与组件边界

自动分析采用系统允许的前后台机会和数据变化触发，不承诺每分钟固定执行。复杂功能显示最后摘要而非持续实时推断；能耗与刷新能力需要实机验证，不以运动会话伪装后台常驻。[S7][S8]

## 13 通用数据来源与质量治理

### 13.1 前台只出现来源

FR-SOURCE-01：任意数量的来源统一抽象为 SourceProfile。界面列出 Apple 健康、导入记录、本应用记录等实际来源及最近数据时间；可展开具体记录来源，但没有固定设备对照面板，也没有固定设备切换主按钮。

来源字段包括 HealthKit sourceRevision、可获得的 device 信息和导入标识。名称、型号或 bundle ID 不能单独作为永久物理设备 ID；无法可靠区分时保留 unknown。来源标识是数据治理信息，不暗示设备正在连接。

### 13.2 原始与派生分层

原始样本按 HealthKit UUID 幂等索引；保留采样时间、单位和删除状态。AI 推断、参考分、用户反馈分别保存，不覆盖原记录。用户改变本 App 来源偏好，不修改 Apple 健康的系统来源顺序。

| 类型 | 治理规则 |
| --- | --- |
| 心率/HRV | 保留并列记录；按情境与来源策略取用，不跨来源直接平均 |
| 睡眠 | 以时间边界切片，重叠只计一次；在床不与分期重复相加 |
| 步数/能量 | 使用经样例验证的统计/聚合策略，不累加所有来源原始累计量 |
| 训练 | 保留来源 ID；重叠需规则与必要的用户确认，不盲目删除 |
| 用户事件 | eventID 幂等，同一事件不重复写系统库 |
| AI 结果 | 引用 EvidencePacket 与策略版本，输入删除后失效 |

### 13.3 冲突与降级

睡眠区间先剔除非法数据，再按起止边界分段；在有记录的片段采用首选来源，缺口可回退并记录回退标记。同一来源分期仍冲突时标为未知，不将稳定排序当作真实分期证据。

来源更新导致个人基线不可比时，标记结构变化并重新积累基线。产品服务同一人的健康档案，不承诺自动分离多人混合记录。AI 必须看到影响判断的质量标记，而不是仅看到清洗后的单一分数。

## 14 实验性算法规格与可复算示例

### 14.1 睡眠参考分 v0.1

令 T 为去重后的睡着分钟数，W 为同一分析窗口中已知清醒分钟数，G 为个人目标分钟数，Δ 为本次睡眠中点相对历史中点的分钟差。使用 D = 100 × min(T/G, 1)，R = 100 × max(0, 1 − |Δ|/120)，C = 100 × T/(T+W)。总分 S = round(0.50D + 0.25R + 0.25C)。

计算条件：T > 0，G > 0，W ≥ 0；至少 7 个有效历史夜晚支持规律基线；睡眠窗口中可分析区间覆盖至少 80%。缺项时 S = nil，不能补 0。120 分钟、80%、7 天和权重均为产品试验参数。

中点基线采用跨午夜可解释的圆周时间统计或将时间映射到用户固定睡眠窗口；不能直接对 23:50 和 00:10 做普通时刻均值。T+W 只对应已知的记录片段，所以 C 标为「记录内连续性」。

示例：T=446，W=18，G=480，|Δ|=18；D≈92.92，R=85，C≈96.12，S=92。深睡 73、REM 99、核心 274 分钟合计为 446 分钟，清醒不计入睡眠。

### 14.2 恢复参考 v0.1

在当日之前的最近 28 天中取至少 14 个有效日，分别建立夜间 ln(HRV) 与静息心率的个人中位数和稳健尺度。尺度建议用 1.4826 × MAD；尺度过小采用明确配置下限或停止输出。下限和离群规则必须版本化。

令 zH = clip((ln(HRV) − median(ln(HRV_history)))/scaleH, −3, 3)，zR = clip((RHR − median(RHR_history))/scaleR, −3, 3)。参考值 Q = round(clip(65 + 12zH − 8zR + 0.20(S−70), 0, 100))。

示例：HRV=54 ms，基线 48 ms，scaleH=0.18；RHR=56 bpm，基线 58 bpm，scaleR=3；S=92。zH≈0.654，zR≈−0.667，Q≈82.59，显示 83。常数 65、权重 12/8/0.20 仅是本原型可解释的启发式设计，不具医疗效度声明。

### 14.3 输出契约

ScoreResult 必含 value 或缺失原因、algorithmVersion、window、inputSampleRefs、baselineWindow、validDays、coverage、sourcePolicyVersion、computedAt。质量与结果分开；不能把数据完整度称为校准置信度。相同输入和版本必须得到相同结果。

## 15 数据模型、版本与一致性

### 15.1 主要实体

| 实体 | 核心内容 | 不变量 |
| --- | --- | --- |
| SourceProfile | 来源信息、别名、首次/末次时间 | unknown 合法，不固定设备数量 |
| HealthSampleRef | UUID、类型、时间、值、单位、来源 | 幂等；删除可传播 |
| SleepEpisode / DailyMetric | 去重睡眠、日聚合、覆盖与样本数 | 缺失为 null，不补 0 |
| ScoreResult | 计算版本、输入、基线、结果/缺失原因 | 同输入同版本可复算 |
| AIProviderProfile | URL、协议、Model、参数、credentialRef | 不存密钥原文 |
| AIPermission | 服务/模型指纹、数据范围、版本、时间 | 修改目的地或扩大范围需重授权 |
| EvidencePacket | 时间窗、事实 ID、摘要、质量、哈希 | 数据最小化且可追溯 |
| AIInference | 任务、模型、模板、证据引用、输出、时效 | 不覆盖事实；错误无有效结论 |
| EmotionEstimate | 倾向、唤醒、正负向、未知项、证据强度 | confidence 未验证时为空 |

| HabitEvent / SyncOutbox | 事件 ID、修订、队列和确认状态 | 重放不重复累计 |
| ActionDraft / AuditRecord | 待确认动作；脱敏调用元数据 | 未确认不执行；不记密钥 |

### 15.2 存储与迁移

HealthKit 保持系统健康记录事实源；SwiftData/SQLite 保存应用内事件、偏好、证据索引与派生缓存。Keychain 保存凭据，普通数据库只持引用。[S20] 不为 AI 无限制复制整个健康库。

原始样本变化、派生缓存失效与 anchored query 锚点推进保持可恢复一致性。恢复备份时重新校验安装身份与健康库锚点，不机械复用旧状态。迁移不改变稳定 eventID，不导致再次写入健康库。

### 15.3 时间、单位与依赖

统一保存绝对时间与时区；睡眠按结束日分桶但时长用绝对时间求差。单位以类型约束，HRV 定义随指标保存。AI 输出必须保留观测窗口与生成时间，不以生成时间覆盖观测时间。

来源策略、算法、提示词、Schema、模型或授权版本变化均可能影响缓存有效性。推断依赖图至少支持“删除一条证据 → 找到受影响结果 → 标记过期/删除 → 必要时重算”。

## 17 隐私、安全与备份

### 17.1 数据与外发授权

FR-PRIV-01：无广告与第三方行为跟踪。健康摘要、习惯、文字上下文分别授权；默认未启用的范围不得进入提示词。仅提供一个自定义 URL 不代表用户同意把所有健康资料发过去。

FR-PRIV-02：首次真实分析显示目的地、Model、字段与时间窗。授权绑定 profile、规范化 endpoint、模型、认证方式和范围版本；切换目的地、模型或扩大范围后重新确认。取消授权立即停止新请求，并取消尚未完成的任务；已发送数据无法在客户端撤回，必须如实说明。

FR-PRIV-03：不自动跨服务降级。服务失败不得将密钥或健康摘要转发到备用域名。即使使用 store=false，也不保证任意第三方代理零保留；数据留存取决于实际接收端政策与部署。[S18]

### 17.2 凭据与网络

正式版密钥放 Keychain，按服务独立绑定；禁止写入代码、URL 查询参数、日志、错误回显、普通偏好或备份。[S20] 变更目的地时原凭据不自动复用。原型仅用内存保管密钥，刷新即清除，不声称拥有原生级安全性。

默认 HTTPS；开发时可显式允许受控本机/私网 HTTP，不接受任意公网明文。拒绝 URL 内嵌用户名/密码、密钥查询参数、片段与危险 scheme；保留代理前缀但规范化末端路径。不跟随带认证信息的跨域跳转，不关闭 TLS 验证。

浏览器原型可能受 CORS 与混合内容策略阻止；不得建议关闭浏览器安全防护或加入未知公共代理。该原型不适合公开部署后输入长期生产密钥。原生客户端和个人自建网关的安全实现需要独立审计。

### 17.3 模型与日志

用户文字、导入内容、来源名称与模型返回都视为不可信数据。使用结构化输入、长度限制和输出转义；不执行 HTML/脚本，不让模型自行改变服务 URL、授权范围、系统规则或调用凭据。

日志仅保留任务、脱敏服务标识、状态、耗时、版本与用量，默认无健康数值、自愿文字原文、密钥或完整提示词。引用 ID 合法不等于结论蕴含关系已验证，仍需评估与审阅。

### 17.4 备份、删除与恢复

正式备份使用审计过的认证加密与密码派生方案；默认只导出用户选定的记录、配置和必要索引，不含密钥、活跃授权或整个 HealthKit 库。导入先校验再原子提交，保留事件 ID，重新校验来源与锚点。

清理原始缓存、删除用户文字、删除派生推断、删除本应用写入的系统样本是不同操作，分别说明与确认。删除证据后使依赖结果失效，不承诺第三方服务已删除远端副本。

原型导出明文演示 JSON，带 synthetic=true；该标记不是判断数据真实性的安全机制。恢复后回到演示模式，密钥和外发授权为空，必须重新配置后才能真实调用。

## 18 免费签名、部署与每周维护

### 18.1 已核验的平台约束

Apple 官方资料列出 Personal Team 的 App ID、设备、安装数量等限制，并说明用于安装的描述文件签发 7 天后到期，需要重新构建和安装。[S1] 因此集中工程能降低维护成本，但不能消除签名到期与标识配额。

App 能否使用某项 capability 取决于开发计划和配置。[S16] 当前交付未使用用户账户进行签名，HealthKit、Watch 安装、附加 target、多设备配额与共享容器都列为第一阶段实机验证项，不能承诺全部自动可用。

### 18.2 建议维护流程

先确认手机和手表近期记录均已保存，导出应用内自定义数据；保持开发团队与 Bundle ID 稳定；在 Mac 的 Xcode 中对原应用覆盖构建和安装；确认手机可启动、健康读取可用、Watch 端可启动；核对自愿文字数量、来源偏好和待同步队列。

默认不先卸载原应用。系统 HealthKit 数据与本 App 沙盒不同，重新安装后的访问还受到系统授权等条件影响；不能把「系统有数据」当作「本地自定义自愿文字不会丢失」。

### 18.3 到期管理与降级

正式版保存人工确认的 profile 到期时间或明确标注的估算时间。仅记录最近安装日不能精确推导签名失效时刻；UI 不展示虚构的「已检测证书剩余 3 天」。每个 target 的有效期可不同，不能只检查手机。

可以在有效期内提醒提前备份与重签，但不保证失效后仍可运行或发送通知。若付费开发者账户将来启用，不应改动核心数据模型；迁移团队或标识前单独做备份与验证。

### 18.4 阻断条件

某项 capability 在个人团队下不可行时，输出真实错误、最小复现与可行降级：先减少扩展、保留手机基础功能或调整分发方式。不得伪造 entitlement、规避系统权限，或假称「合成一个 App 就没有限制」。

## 19 复用策略与供应商适配

### 19.1 复用什么，不复用什么

优先复用成熟的睡眠图表、HealthKit 查询封装、原生页面组件和同步样例，而不是拼接多个完整 App。SleepChartKit、Zwäg、Ritmo 等是此前登记的候选；本轮未重新编译或审计这些仓库，实施前必须锁定 commit 并检查实际 LICENSE、二级依赖、素材和最低系统版本。[S13][S14][S15]

公开源码不等于无条件商业许可，也不证明其压力/恢复算法有效。无需把第三方“情绪得分”作为真实标签；自动情绪模块采用独立证据、质量门控与评估流程。

### 19.2 API 适配原则

优先实现 OpenAI 兼容 Chat Completions，并提供独立 Responses 与 Anthropic Messages 适配器。三者请求/返回字段分别处理，不通过简单改 URL 复用全部逻辑。[S17][S18][S21]

自建服务可使用兼容端点；例如 Ollama 文档说明其支持 OpenAI API 的一个子集，因此模型列表、结构化输出和参数支持仍要按实际版本探测。[S22] 不硬编码某一模型名，也不承诺用户账号一定有某模型权限。

本原型为原创 HTML/CSS/JavaScript，无第三方运行时、远程字体或图片 CDN。默认不请求外网；真实模型请求只有在明确授权后出现。产品未来发布的许可证由项目维护者决定。

## 20 视觉、交互与异常状态

### 20.1 视觉方向

延续蓝灰与柔和绿色，产品名称统一为 watch you。AI 结果采用简短解释卡而非大面积聊天气泡；情绪用中性倾向与时间线，不通过恐吓式红色暗示诊断。来源作为轻量元信息，不在首页堆叠设备图标与数量。

手机支持动态字号、VoiceOver、合理触控区域、减少动态效果与深色模式；手表坚持一个主结论和一个主要操作。原型固定像素仅为评审，不作为原生适配规范。

### 20.2 必须有的状态

| 状态 | 应展示 | 不应出现 |
| --- | --- | --- |
| 未配置 AI | 配置入口、可用原始数据 | 随机情绪结果 |
| 演示模式 | 演示标识与模拟数据说明 | “已完成真实分析” |
| 真实模型分析模拟数据 | 模型名 + 合成数据标识 | 真实 HealthKit 接入暗示 |
| 无可读健康记录 | 多种可能原因 | 无依据判断权限被拒绝 |
| 基线不足/运动干扰 | 原因与未知状态 | 默认正常、满分或低压力 |
| 历史数据 | 观测日期与缓存标识 | 将生成时间说成采样时间 |
| 认证/限流/超时 | 原因、重试/配置入口 | 失败后假成功 |
| 返回不合规 | 拒绝采纳、保留原始事实 | 直接把原文显示为结论 |
| 取消/配置改变 | 丢弃过期任务结果 | 旧响应覆盖新结果 |
| 手表离线 | 最后摘要时间、离线事件队列 | 实时分析或已同步假象 |

### 20.3 交互约束

AI 标识点击后能看到模型、任务范围、时间与依据。数据加载失败不可无限转圈；每次点击不应无限增加重试。删除、导入替换、外发授权和执行 AI 动作均有清晰确认；普通本地记录支持撤销。

### 21.2 主要风险

技术风险包括 Personal Team 能力、历史数据可读范围、背景调度、来源不可区分、网络兼容、密钥误发与离线重复；分别通过探针、按可见范围导入、事件触发、unknown、适配器和幂等实现处理。

产品风险包括把 AI 当作测量仪器、健康分数过度精确、把生理唤醒等同于心理情绪以及模型幻觉。通过证据分层、强度而非准确率、未知状态、输出校验和小范围效果评估控制，不靠一句免责声明替代设计。

### 21.3 非功能目标

缓存首页可见内容 P95 < 1 秒、本地习惯记录确认 P95 < 300 ms 为待测目标，需指定参考设备和数据量。AI 延迟独立测量，不用网络响应阻塞事实展示。推断并发初始为 1，任务可取消，失败重试有上限。

耗电、后台机会、签名到期、隐私保留和医学效果没有实机证据时不标为已通过。上线前必须清理演示数据、检查密钥与日志、验证空状态、审计许可证并明确模型服务的使用限制。

## 25 AI 设置详细规格

### 25.1 服务与认证字段

| 字段 | 类型/默认 | 规则 |
| --- | --- | --- |
| name / profileID | 可读名 / 稳定 ID | 多组服务相互隔离，原型最多 8 组 |
| protocol | chat / responses / anthropic | 每种协议独立构建与解析 |
| baseURL | 用户输入，默认空 | HTTPS；不含用户密码、查询串、片段 |
| model | 用户输入，默认空 | 手填或列表选择，不预设一定可用 |
| authType | bearer / x-api-key / none | none 必须明确选择 |
| credentialRef | 安全存储引用 | 正式版 Keychain，原型内存 |
| temperature | 默认省略 | 能力允许时发送；留空不硬填 |
| maxOutputTokens | 初始 1200 | 按协议映射；原型 64–16000 |
| tokenField | max_tokens / max_completion_tokens | 兼容服务按实际支持配置 |
| timeout | 初始 45 秒 | 原型 5–180 秒；可取消 |
| dailyRequestLimit | 初始 20 次 | 请求次数而非费用估算，原型上限 200 |
| allowLocalHTTP | 默认关闭 | 仅本机/明确私网开发；拒绝公网明文 |

不同模型对 temperature、JSON Schema、推理 Token、流式与 Token 字段的支持不同。正式版可保存能力探测结果；不在遇到 400 后静默改变全部参数并无限重试。[S17][S18]

### 25.2 功能与数据范围

模块开关覆盖今日、情绪、睡眠、心率、恢复、活动、习惯、趋势报告与问答。数据范围单独控制睡眠、生理指标、活动、习惯、自愿文字与反馈。开关某功能不自动扩大范围；范围为空时显示原因，不虚构结论。

首版采用一组全局默认模型，多组配置可快速切换；按模块绑定专用模型属于后续增强，不能把当前原型的配置列表误称为多模型并行路由。

### 25.3 测试、保存与重授权

保存只进行本地校验与安全存储，不立即发健康数据。模型列表请求与无健康数据生成测试需展示目标地址并由用户触发；列表端点不可用仍允许手填模型。测试成功只证明该次请求成功，不证明健康推断正确。

修改 URL、认证方式时清理旧密钥绑定；服务、模型、数据范围变化后清除旧同意。配置导出排除密钥和外发授权。以后增加自定义 Header 时需分类为普通/秘密字段，禁止覆盖 Host/Cookie 等危险头，秘密字段进入安全存储；原型尚未实现任意自定义 Header。

### 25.4 费用与失败

显示调用次数、状态和可获得的 usage；没有定价元数据不虚构费用。第三方付费服务是否可用取决于用户账号与服务端。原型不保存钱包、自动充值或绕过额度。

## 26 AI 输入输出契约与校验

### 26.1 EvidencePacket

证据包包含 schemaVersion、task/module、synthetic 标识、时间窗、基线有效日、facts、质量标记和当前问题。每项 fact 必含稳定 id、metric、value/null、unit、sampleCount、window、sourceRef；文字情境标明用途与授权，不作为系统指令。

发送前由代码从权限白名单构造字段，而不是先组装整个健康库再要求模型“不要看未授权部分”。对服务端只暴露任务必要来源类别，不默认发送设备序列号、姓名、账号、精确位置或自愿文字原文。

### 26.2 标准结果

正式结果包括 summary、claims、evidenceRefs、uncertainties、suggestions、emotion（按任务）、generationMetadata、dataWindow 与 validUntil。claims 应逐条关联证据，便于区分观察、解释与建议。

原型采用简化契约：summary、evidenceIds、uncertainties、suggestions、emotion。emotion 包含 status、label、arousal、valence；解析后由本地附上证据强度、模型与时间，不信任模型自行填写来源/生成元数据。

FR-VALID-01：校验 JSON、字段类型、长度/枚举、输出截断、引用存在性与数据窗口；不允许额外信息触发动作。FR-VALID-02：没有情境时不得给确定正负向，缺少有效证据不输出强结论。FR-VALID-03：引用 ID 通过只是必要条件，不证明语义受证据支持，仍需对过度推断进行评估。

### 26.3 提示词与返回隔离

系统模板明确健康数据仅用于低风险解释、禁止诊断和编造、允许弃答、要求引用。用户问题和导入资料以序列化数据块传入，不拼入系统规则。返回使用文本渲染与转义，不执行 HTML、链接指令或代码。

模型输出失败时不展示未经校验的内容为正式结论；可在开发日志中记录脱敏错误类别，但不保留完整敏感原文。结果修复最多采用可见、有预算的单次流程；原型不自动重试修复，避免额外费用与循环。

## 27 自动分析调度与个性化

### 27.1 触发条件

候选触发包括前台打开、授权完成、HealthKit 增量更新、睡眠主段结束后的新摘要、手动刷新和已确认的用户反馈。系统只在拥有运行机会时调度，不承诺固定轮询。手表和手机不得为同一证据包各自重复调用模型。[S7][S11]

每次先判断授权、模块开关、数据时效、质量、缓存与预算，再进入单任务队列。可把相近更新合并成一个窗口，避免每条心率样本触发一次大模型。建议初始至少 30 分钟的自动情绪重评间隔，仅作待测能耗参数；重要新证据是否提前重评由规则决定。

### 27.2 并发与失败

任务持有配置代次和输入哈希；配置改变、撤销授权、证据删除或更新时取消旧任务。即使取消时响应已在途中，也必须在提交结果前重新检查代次。认证失败停止自动重试，限流遵循退避与预算；失败不跨服务转发。

原型只在当前页面与数据状态变化后演示自动触发，采用相同输入不重复、并发一条、失败不自动循环；原生后台合并窗口、退避、系统约束和低电量策略尚待实现。

### 27.3 自适应与提醒

个性化先学习稳定的个人数据基线与建议偏好，不默认训练模型、不上传反馈用于训练。自愿纠正可用于检验偏差；若开展个人模型适配，明确告知训练范围并保留独立时间验证。

提醒默认只针对用户启用的低风险习惯；持续状态变化也应先在应用内解释，不因一次“可能紧绷”反复打扰。正式版保留静默时段、每日上限与关闭入口，不能声称对心理危机提供实时可靠预警。

## 28 版本变更与仓库交接
