# watch you · 原生开发任务书

版本 v2.0；需求基线 2026-10-21。仓库目标 `Yurken/watchYou`。开始前读取 `watch_you_PRD.md`、本任务书和 `tests/TEST_REPORT.md`，不得把演示截图当作原生实现证据。

## 不可改变的产品方向

展示名称一律为 **watch you**，代码标识允许 WatchYou。情绪默认 AI 自动推断，不需要每日打卡。手动背景与纠正仅是可选辅助。AI 是首版跨模块能力，不得推迟成一个空聊天入口。首页与导航不展示固定设备数量、固定对比卡；数据来源保持通用、可扩展，并保留后端重叠处理能力。

服务 URL、Model、协议、认证、密钥和参数由用户配置。一个工作区包含手机与手表，不据此声称只占一个 App ID。不要求服务器或云账户作为本地数据查看的前提。

## 真实性和交付规则

开发报告分成“已实现、已测试、未验证、阻断项”四部分。仅在实际运行命令且保存输出后写测试通过。无法在当前机器执行 Xcode/设备测试时明确报告环境缺失，继续完成可独立验证的逻辑，不伪造成功日志。

Mock 只能在显式 Demo 配置启用。真实查询失败不能返回示例心率；真实模型失败不能返回固定文本并标记成功。所有样本、推断和截图标明来源与时间。严禁输出医学准确率、能耗成绩或签名成功等未经实测的数值。

任何真实健康资料或凭据不进入仓库、日志、测试夹具或公开 Issue。模型响应不执行 HTML、代码、指令或外部动作。对外发布前由用户决定许可证和分发方式。

## M0：平台与模型探针

先列出实际 Mac、Xcode、iOS、watchOS 与设备型号，不猜版本。建立可启动的最小 iPhone/Watch 配套工程，验证个人团队签名、HealthKit capability、按需读取一类数据、WatchConnectivity 往返、原标识覆盖重签。

同时实现模型配置最小闭环：URL/Model/认证输入 → Keychain 保存 → 不含健康数据的连接测试 → 清晰错误。先接通一个用户指定的兼容服务，不将所有服务的成功视为默认。

验收证据：实际 build 命令和结果、安装步骤、可读记录数量/时间的脱敏结果、双向消息编号、重签前后本地事件数量。阻断时保存原始错误类别、最小复现和可行降级，不伪造 entitlement。

## M1：数据与 AI 基础

实现 HealthRepository、SourceResolver、EvidenceBuilder、CredentialStore、AIProvider、ConsentStore、InferenceCache、Clock 等可注入接口。

HealthKit 授权结束不等于可读授权全获准。空结果使用 unknown/empty，不断言拒绝。根据真实授权历史范围导入，增量锚点、新增与删除保持事务一致。以 UUID 幂等；时间内部统一绝对值，保留时区。睡眠区间并集排除在床重复，心率冲突保留来源，不直接平均。

AIProvider 至少独立定义请求构建、鉴权、超时、取消、响应解析、输出校验与错误映射。兼容接口不是完全等价；按模型能力决定是否发送 temperature、结构化输出和 Token 字段。Chat、Responses、Messages 的 mock 夹具分开，不跨协议猜解析。

Keychain 凭据绑定配置身份与接收端；配置文件只存引用。URL 禁止带用户密码、查询密钥、片段和危险协议。默认 HTTPS；开发私网 HTTP 需单独开关与网络权限验证，不全局关闭传输保护。重定向不能携带密钥到未确认地址。

按白名单构造 EvidencePacket，不先组装完整健康库。系统/开发模板与用户文字分离。每次请求携带证据 ID、窗口、单位、样本数、质量、sourcePolicyVersion、dataVersion 和 synthetic 标志。

验收：部分授权、零记录、删除重算、区间重叠、数据单位、时区、来源未知、错误 URL、密钥隔离、日志脱敏和三种协议 mock 均有自动测试。

## M2：自动情绪推断闭环

实现候选触发 → 质量门控 → 摘要与缓存 → 模型推断 → 输出验证 → 情绪卡与手表摘要。触发来自可用的系统运行机会与新数据，不伪装固定全天实时采样。相同摘要仅调用一次；有新证据或版本变化才失效。调用频率、预算和单并发默认值可配置。

情绪实体与本人反馈分开。保存唤醒倾向、正负向/未知、有限标签、证据强度、数据时效、模型和生成版本。仅有生理信号时允许估计唤醒倾向；不要把紧绷写成焦虑诊断，也不要在缺少情境时保证具体情绪。门控缺失、过期、正在运动或明显混杂时保留 unknown / insufficient。

推断不是 HKStateOfMind 中的本人自述；除非用户明确确认并授权，否则不自动写入。纠正保留原结果、反馈时间与版本，不能把模型自己的输出再当训练真值。个性化评估需要独立时间留出和自愿反馈，不能用同一批反馈训练并自证准确。

验收：无打卡也可分析；条件不足可弃答；推断与反馈来源清晰；旧任务不能覆盖新配置；无效 JSON、截断、未知证据、无依据强结论被拦截；失败不显示演示成功。

## M3：全模块 AI 与统一设置

今日为综合摘要；睡眠解释作息与缺口；心率解释个人基线和情境；恢复解释输入贡献而不改分；运动总结既有记录；习惯提出可确认的小目标；趋势/周报引用有效样本；助手只在用户授权范围回答。

每个模块采用相同状态组件：未配置、未授权、等待数据、排队/运行、结果、历史缓存、失败、关闭。所有 AI 卡片能够展开依据、窗口、模型与不确定性。不得用一个“AI 功能”按钮代替这些模块的实际接入。

设置包含配置列表、URL/Model、认证/密钥、协议、参数、模型列表/测试、任务开关、外发字段、自动调度、预算和脱敏调用记录。切换端点清理旧密钥绑定；服务、模型与范围变化需要重新确认。保存不自动发数据，恢复备份不恢复活跃授权。

可执行建议如改目标、设提醒必须由用户单独确认；对话本身不触发写入。异常趋势不等于急症判断，不能暗示替代系统安全功能。

## M4：手表、离线与维护

手表显示手机生成的最新摘要及数据时间；不独立重复调用同一份摘要。饮水、呼吸等用户事件持久化到 outbox，事件 ID + revision 幂等，接收端保存后再确认。不要用会覆盖旧状态的 context 传输累积事件。

来源治理不依赖设备固定数量或设备名称作为永久 ID。存在无法识别的来源时标 unknown；切换或重装保持可恢复，UI 不增加固定设备对比入口。

备份采用经审计的认证加密方案，凭据不导出；导入临时校验、事务提交，失败不部分覆盖。维护页只展示人工确认/明确估算的签名到期信息，不假装读取真实证书。覆盖重签前后核对本地记录、队列、健康查询与密钥状态。

验收：实际断连/重连、进程终止、重复消息、旧消息到达、删除墓碑、重签、授权变化、加密备份损坏与迁移。Widget/复杂功能等扩展在核心可用后逐项加，不因它们阻塞基础维护。

## M5：验证与发布

使用自愿的小范围观察，分开评估数据完整性、推断覆盖、弃答、用户纠正率和误导性建议。评价口径、样本数和时间拆分必须可复核；不凭单次主观认可宣传准确率。真实能耗测试需指定设备和使用条件。

发布检查：清除默认示例值、审计所有源数据与日志、验证无网络降级、最大字体/VoiceOver、模型费用提示、第三方许可证与用户分发权限。当前 PRD 中“目标”不自动变成“已完成”。
